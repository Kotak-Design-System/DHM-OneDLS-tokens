# Figma Variables

Generated by DHM Tokens. This file explains how the token source is organized for designers, developers, and AI-assisted tooling.

## Token source

The canonical developer-facing source is DTCG JSON. References are preserved where the source workspace contains aliases. The lossless plugin snapshot is stored separately at `.dhm/workspace.project.json` so the workspace can be restored without losing Figma metadata, formulas, scopes, or plugin-only structure.

## Naming conventions

Token paths use dot-separated names in DTCG files and are normalized to slash-separated groups when synchronized into Figma. Prefer stable, semantic names and keep primitive values separate from contextual aliases.

## Usage guidelines

- Designers can edit the source in DHM Tokens and use the plugin snapshot for a lossless round trip.
- Developers can consume the DTCG files directly from the repository.
- AI tools should read the DTCG token values, types, descriptions, and references before generating code or design decisions.
- Pull changes into DHM Tokens before pushing again when the repository has changed outside the plugin.

## Sync notes

GitHub sync creates one atomic commit containing the DTCG source, this guide, and the lossless plugin snapshot. Fine-grained personal access tokens are kept locally by the plugin and are never written to the repository.
